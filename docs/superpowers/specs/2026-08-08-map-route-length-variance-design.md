# 지도 루트 길이 편차 설계

작성일: 2026-08-08

## 배경

`generateMap()`(`src/game.js:1280`)은 시작(column 0)부터 보스(column 5)까지 항상 정확히 6개 컬럼을 거치는 고정 레이어 구조다. 각 컬럼의 노드는 오직 바로 다음 컬럼으로만 연결되므로, 어떤 경로를 선택해도 거치는 노드 수는 항상 동일하다.

## 목표

- 일부 경로는 기존보다 노드 하나가 늘어난 우회 경로(최대 7~8개)를, 일부는 하나가 줄어든 단축 경로(최소 5~6개)를 선택할 수 있게 한다.
- 보상은 별도 배율 없이 "경로가 길수록 전투/이벤트/보물 노드를 더 많이 지난다"는 자연스러운 결과로 비례하게 둔다.
- 기존 렌더링(베지어 곡선 연결, `drawMap`/`drawMapNode`)과 노드 그래프 순회 로직(`travelTo`, `availableNodes`, `currentNode`)은 변경하지 않는다 — `node.next` 배열과 `node.x`/`node.y` 좌표만으로 동작하는 기존 구조를 그대로 활용한다.

## 범위

### 포함

- `generateMap()`에 두 가지 변형 추가:
  - **단축 경로**: 컬럼 1~3의 노드 중 일부가 바로 다음 컬럼이 아니라 그다음 컬럼(컬럼+2)으로 직접 연결되는 경우를 추가한다. 기존의 "가장 가까운 다음 컬럼 노드 1~2개 연결" 로직에 더해, 낮은 확률로 컬럼+2 직행 연결을 추가 옵션으로 부여한다.
  - **우회 경로**: 컬럼 1~3의 노드 중 일부가 다음 컬럼으로 바로 가는 대신, 그 사이에 새로 생성되는 "우회 노드"(소수점 컬럼 값을 가지는 이벤트/전투/보물 중 하나)를 거쳐 같은 다음 컬럼에 합류하는 선택지를 추가로 연다.
- 우회 노드는 `column`에 소수 값(예: `column + 0.5`)을 사용해 `x = 78 + column * 207` 공식이 그대로 적용되어 두 기존 컬럼 사이에 자연스럽게 배치되도록 한다.
- 새 테스트: 생성된 지도에서 시작→보스까지의 최단/최장 경로 길이에 실제로 편차가 있는지, 그래프가 항상 도달 가능한지(dead end 없음) 확인한다.

### 제외

- 보상 수치나 확률에 경로 길이 기반 배율을 추가하는 것 (자연스러운 노드 수 차이로 충분하다고 판단).
- 액트(전투 실력 밸런스)별로 다른 편차 폭을 적용하는 것 — 모든 액트에 동일한 규칙 적용.
- 지도 시각 디자인(선/노드 스타일) 변경.

## 알고리즘 개요

`generateMap(actIndex)` 내부에서 컬럼 1~3에 대해서만 아래 로직을 적용한다 (컬럼 0=시작, 4=전투/정예, 5=보스는 그대로 유지):

1. 기존처럼 각 노드가 다음 컬럼에서 가장 가까운 노드에 연결한 뒤, 72% 확률로 두 번째 가까운 노드에도 연결한다.
2. **단축 연결**: 컬럼 1, 2의 각 노드에 대해 25% 확률로, 다음 컬럼을 건너뛰고 그다음 컬럼(컬럼+2)의 가장 가까운 노드에 직접 연결하는 엣지를 추가로 연다 (기존 다음 컬럼 연결은 그대로 유지 — 즉 플레이어가 선택 가능한 옵션으로 추가되는 것이지 대체가 아니다).
3. **우회 연결**: 컬럼 1, 2의 각 노드에 대해 25% 확률로(단축 연결과 배타적으로 굴림), 우회 노드를 하나 생성해 `column + 0.5`, `row`는 두 인접 컬럼 사이의 값으로 배치하고, 해당 노드→우회 노드→다음 컬럼의 가장 가까운 노드로 이어지는 경로를 추가로 연다. 우회 노드의 `type`은 `["event", "battle", "treasure"]` 중 무작위로 정한다.
4. 도달 불가 노드 방지 로직(기존의 "다음 컬럼 중 들어오는 연결이 없는 노드는 가장 가까운 이전 컬럼 노드에 강제 연결")은 우회 노드를 포함한 전체 노드 목록에 대해 그대로 적용한다.

## 테스트 및 검증

- `generateMap(0)`을 여러 번 호출해, 그래프 상 시작에서 보스까지의 최단 경로 길이와 최장 경로 길이를 BFS로 계산했을 때 서로 다른 경우가 실제로 나오는지 확인하는 테스트를 추가한다 (완전히 결정론적이진 않으므로, 여러 시드에 걸쳐 "차이가 나는 경우가 존재한다"를 검증).
- 모든 노드가 `next` 배열을 통해 보스 노드까지 도달 가능한지 확인하는 테스트를 추가한다 (dead end 방지).
- 우회 노드가 있는 지도에서도 `currentNode()`/`availableNodes()`/`travelTo()`가 기존과 동일하게 동작하는지 (이 함수들은 `column` 값의 정수 여부에 의존하지 않으므로 별도 수정 없이 통과해야 한다) 확인한다.
